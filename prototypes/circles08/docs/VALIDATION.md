# Circles08 — 検証項目

作業場所は `prototypes/circles08/` です。[共通の終了チェック](../../../docs/agent/VALIDATION.md)も使用します。

## 自動テストと production build

```sh
npm test
npm run build
```

両方が終了コード 0 で完了することを確認します。テスト失敗・ビルドエラーを残したまま `main` に反映しません。新しい警告が出た場合は内容と影響を調べます。

テストは初期配置、物理、手の座標変換、追跡ライフサイクルなどを確認します。実際の GPU 描画、カメラでの認識精度、投影時の使い心地は自動テストだけでは確認できません。

ビルドではこの案の `dist/` と `dist-zipped/project.zip` が生成されます。ビルド設定やフォルダーを変更した場合は、ZIP と `dist/` のファイル・内容が一致し、JavaScript の分割ファイルと CSS がすべて含まれることも確認します。

## ブラウザーの基本確認

1. 開発サーバーを起動し、表示された localhost URL を開きます。エラーのない初期表示を確認します。
2. 球・箱・棒が表示され、中心へ動くこと、FPS が更新されることを確認します。
3. 利用可能な Color / Difference / Normal を切り替えます。Color 非対応端末で Difference に移る場合は、その制約を記録します。
4. 変更したパラメーターの前後を同じ seed で比べます。
5. Pause と Replay same layout、ウィンドウのサイズ変更を確認します。
6. Save image が PNG を出力し、操作パネル・FPS・カメラ映像を含まないことを確認します。手の位置を示す赤い点は描画の一部として含まれます。
7. 保存した既定値が再読み込み後にも反映されることを確認します。

描画・操作変更では関連する項目を実際に確認します。起動経路やパッケージ構成を変更した場合は production の `dist/` を静的 HTTP サーバーで配信した表示も確認します。HTML の直接オープンでは確認しません。

## 本人の協力が必要なカメラ確認

プライバシー設定の変更やログインを代理で推測せず、本人に必要な操作だけ依頼します。生の映像を保存・共有する必要はありません。

- Digit を選び Start tracking。カメラ許可後、近くに映した手で赤い点が動き、物体を押せること。
- Kinetic を選び、上半身と両手が入る位置で左右の手を確認すること。
- Source 切り替えで古い追跡が残らず、選択中の mapping だけが表示されること。両 Source の値がページ内で別々に保持されること。
- Mirror が映像と操作の左右に反映されること。
- Stop camera で映像・追跡が止まること。途中で停止・再開しても動作すること。
- タブから離れて戻った時や Pause / Replay 後に、古い手の位置が残らないこと。

追跡関連を変更した場合は該当項目を優先します。使用できるカメラや本人の協力がない場合、未確認の項目を具体的に記録します。

## 実際の設置・投影で確認すること

同じ seed と設定を使い、解像度・物体数・追跡モード・カメラとの距離・照明条件を記録します。操作範囲、奥行き、押す強さ、FPS を確認します。別 PC でのビルド成功を、この環境の性能や認識品質の保証としません。
