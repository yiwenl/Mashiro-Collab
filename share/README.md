# 共有ノート

受け取った人に、**何を用意したか、その理由、試してほしいこと**を伝える場所です。共同作業が始まった後は、更新内容と変更の理由もここに残します。コードと一緒に Git で共有します。

## 読む時

初めて受け取った時は、下の「初回共有の案内」から読みます。共同作業の再開時は、最新の `main` を取り込んだ後、前回以降の関連ノートを読みます。agent は内容と試してほしい点を、相手に短く説明してください。

各ノートは変更の意図と当時の確認結果を伝える記録です。現在の操作方法や作業ルールは [AGENTS.md](../AGENTS.md) と対象プロトタイプのガイドを参照します。

## 書く時

- **共有する更新がまとまった時に一件**書きます。細かい commit ごとに作る必要はありません。
- [TEMPLATE.md](TEMPLATE.md) を使い、`YYYY-MM-DD-short-topic.md` として保存します。同じ日の別更新は話題を変えて別ファイルにします。同名があれば他の記録を上書きせず、名前を具体化します。
- 日付には実際の作業日を使います。ファイル名の話題は英小文字・数字・ハイフン、本文は日本語を基本にします。
- 技術経験のない相手にも伝わるよう、見た目や操作への影響を先に書きます。ファイル名の一覧や commit メッセージのコピーだけで済ませません。
- 初回共有では、用意した内容とその目的を紹介します。相手がまだ受け取っていない版との比較や、内部の準備作業を、相手が経験した過去として書きません。更新時の比較は実際に共有した内容を基準にします。
- 「なぜ」は実際の依頼や比較結果に基づきます。まだ試している案は、そのことが分かるように書き、最終決定と混同させません。
- 確認済み・未確認を分け、相手に試してほしいことを具体的に書きます。必要な準備や起動場所が変わった場合も伝えます。
- ノートは変更と同じ commit、または同じ作業ブランチの commit に含め、同じ `main` への反映で共有します。統合中に内容が変わった場合はノートも合わせます。
- ノート自身を含む commit ID や push 成功の宣言は必須にしません。push 結果は確認後にチャットで報告し、その追記のためだけに追加 commit を作りません。
- 過去のノートは残します。誤記の訂正以外は新しい更新ノートを追加します。変更も共有すべき発見もなければ空のノートは不要です。

詳しい実験メモが必要なら対象の `docs/sessions/` に置き、ここからリンクします。このフォルダーには相手への短い説明を残してください。
