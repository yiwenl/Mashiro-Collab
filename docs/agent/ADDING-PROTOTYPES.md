# 新しいプロトタイプを追加する

## 分ける基準

表現や操作方法の別案を比較する場合は `prototypes/<id>/` を追加します。既存案の単純なパラメーター調整はその案の中で行います。どの案も自動的に最終版と扱いません。

ID は内容を識別できる安定した英小文字・数字・ハイフンを使います。既存の `circles08` は移行前の名前を保持しています。`final`、`latest` のように後で意味が変わる名前を避けます。

## 追加するもの

各案に、その案だけで準備・実行できる情報を含めます。技術の選択は案ごとに自由です。Node.js を使用する場合の例:

```text
prototypes/<id>/
├── README.md
├── .nvmrc
├── package.json
├── package-lock.json
├── src/
├── public/
├── config/
├── test/
└── docs/
    ├── ADJUSTMENT.md
    └── VALIDATION.md
```

不要な空フォルダーは作りません。Node.js を使わない案では適切な依存管理ファイルと実行手順を用意します。必要なら `vendor/` と出典・ライセンス情報を含めます。

README には、何を試す案か、未確定の部分、必要な環境、インストール・起動・停止、URL / ポート、操作、保存方法、検証コマンド、既知の制約を書きます。共通の Git 手順は [ルートの AGENTS.md](../../AGENTS.md) にリンクし、複製しません。

## 独立性

- `.git/` はルートの一つだけです。プロトタイプ内で `git init` しません。
- 依存関係は各案で宣言・固定します。別の案の `node_modules/` に依存させません。
- 相対 import で別プロトタイプの内部ファイルを使いません。共通化が必要になった時に別途設計します。
- 同時起動する案には異なる既定ポートを割り当て、使用ポートをルートの一覧に書きます。circles08 は 8083 を使います。
- ビルド成果物はその案のフォルダー内に出力し、他の案の `dist/` を消さないようにします。
- 既存案を元にする場合、`node_modules/`、`dist/`、`dist-zipped/`、個人のログはコピーしません。名前・説明・ポート・出典を更新します。
- 古い計画を引き継ぐ場合は `docs/history/` に置き、過去の指示が現行ルールではないことを明示します。

## 追加後の確認

1. 新しい案の依存関係をそのフォルダーでインストールします。
2. その案の起動・操作・テスト・ビルドを確認します。必要な実機がない場合は未確認範囲を記録します。
3. ルートの [一覧](../../README.md) に目的、状態、環境、ポート、README へのリンクを追加します。
4. 新しい種類の生成物がある場合だけ、ルートの `.gitignore` を補います。既存の `node_modules/`、`dist/`、`dist-zipped/` は各階層で除外されます。
5. 既存案のソースと起動経路を壊していないことを確認します。
6. [Git の終了手順](GIT-WORKFLOW.md) で共有します。
