# 調整の進め方と保存

## 対象と希望を特定する

ルートの [一覧](../../README.md) から対象を特定します。依頼された案を調整し、別の案へ同じ変更を自動適用しません。「今の案の調整」か「別の方向の追加」かで作業場所が変わります。

利用者の表現を具体的な見た目や反応に結び付けます。例えば「ゆっくり」は移動速度・揺れの収まり方など複数の意味があり得ます。既存の画面と希望を比べ、不明な点だけ短く確認します。

現在の [circles08 専用ガイド](../../prototypes/circles08/docs/ADJUSTMENT.md) には、画面の設定名と編集ファイルの対応があります。別の案ではその案のガイドを使います。

## 小さく試し、保持する値を保存する

1. 同じ条件で比較できるよう、元の設定、URL / seed、対象バージョンを記録します。
2. 既存の操作パネルで試せる場合は、関連する少数の値から調整します。
3. 利用者に見た目や操作感を確認してもらいます。UI の数値だけで望ましい結果を推定しません。
4. 保持したい設定を、その案の設定ファイルへ書き戻します。セッション中だけ試した値を勝手に全部既定値へ変更しません。
5. 再読み込みや再起動後に、保存した値と動作が再現されるか確認します。
6. [検証](VALIDATION.md) と [Git の終了手順](GIT-WORKFLOW.md) を実行します。

circles08 の GUI の値はページ内だけで有効です。URL の `fxhash` は初期配置を再現しますが、GUI の全設定や手の動きは保存しません。

## ソースを変更する場合

- 先に対象の README とファイル構成を読み、設定変更で足りるか確認します。
- 操作項目、既定値、保存方法が変わったらその案の文書も同じ変更に含めます。
- 共通ライブラリ化や他の案への依存追加は、単なる調整と分けて必要性を判断します。
- 同梱ライブラリの更新は通常の見た目調整に混ぜません。circles08 の `vendor/` と MediaPipe のバージョンは対応関係があるためです。
- 大きく異なる表現を試す場合は [新しいプロトタイプの追加](ADDING-PROTOTYPES.md) に従い、元の案を残します。

## 試した結果を残す

共有する変更内容と理由は [share/](../../share/README.md) に、相手向けの短い更新ノートとして残します。すべての操作ログを保存する必要はありません。

比較対象、選んだ値、見送った案など詳しい実験記録が必要な場合は、対象プロトタイプの `docs/sessions/YYYY-MM-DD-topic.md` に分け、更新ノートからリンクします。実際の日付を使い、個人情報や生のカメラ映像を自動添付しません。作業結果の報告形式は [検証ガイド](VALIDATION.md) を使用します。
