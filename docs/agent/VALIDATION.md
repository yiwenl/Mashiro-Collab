# 検証と作業結果の報告

## 起動だけを依頼された時の引き渡し

[環境と実行](SETUP-AND-RUN.md)に従い、次を確認します。

- [ ] 利用者の PC で、共有 `main` の更新と対象の依存関係の準備ができた。
- [ ] コンパイルに成功し、実際の URL が対象の HTML を返すことを確認した。
- [ ] 利用者に見えるブラウザーで開いた、または HTTP 接続を確認したクリックできる URL を渡した。ポートを変えた場合はリンクも合わせた。
- [ ] ブラウザーを操作できる場合は図形・操作パネル・FPS とエラーを確認した。操作できない場合は画面未確認と伝えた。
- [ ] 返信後もサーバーが動く状態を保ち、URL と停止方法を伝えた。

これが初回起動の完了条件です。全テスト・production build・カメラの操作確認は、最初の画面を開くための前提ではありません。変更がなければ更新ノートや commit / push も不要です。画面を直接確認していない場合やカメラ未使用の場合に、それらを検証済みとは報告しません。

## 変更がある場合の検証の範囲

各プロトタイプの README / 検証ガイドで実際のコマンドと期待結果を確認します。現在の [circles08 の検証項目](../../prototypes/circles08/docs/VALIDATION.md) を別の案へ無条件に適用しません。

- 最初に現在の動作を確認し、既存の問題と今回の変更による問題を分けます。
- 調整中は変更した箇所を中心に確かめます。
- 保持するコード・設定を `main` に反映する前には、対象の自動テストと production build を実行します。
- 最新 `main` を取り込んだ後は、統合した状態で必要な検証を行います。
- 見た目や入力操作に関係する変更はブラウザーで確認します。ビルド成功だけでは見た目の正しさを保証しません。
- 複数の案や共用の仕組みを変更した場合は、影響する案をすべて検証します。

文書のみの修正ではリンクと手順の整合を確認します。ソースの移動や起動コマンドの変更を含む場合は、実際のインストール・起動・テスト・ビルドも確認します。

## できない検証を明示する

カメラ、身体の動き、投影会場の条件は本人の協力が必要になることがあります。確認したい操作と期待結果を一つずつ案内します。

未確認事項は「未確認」と記録してください。既存の未確認事項を明示したうえで、関係のない検証済み変更は共有できます。一方、今回の変更の成否を判断するために不可欠な確認ができていない場合やテストが失敗している場合は、作業ブランチに保存して未完了とします。

過去の `docs/history/` にあるテスト結果は、今回の実行結果ではありません。実行していない検証を実施済みと報告しません。

## 変更を共有する時のチェック

- [ ] 今回で保持する変更と、対象プロトタイプが明確である。
- [ ] 一時的な GUI 設定を保持したい場合、ソースへ保存して再読み込みを確認した。
- [ ] 必要なテスト・ビルド・画面確認に成功した。未確認事項も区別した。
- [ ] 変更した操作・設定・ファイル構成を文書に反映した。
- [ ] 共有する更新について [share/](../../share/README.md) に、変更内容と理由、試してほしいこと、確認済み・未確認を記録した。
- [ ] 一時ファイル、生成物、認証情報が commit に混ざっていない。
- [ ] 今回の変更が commit され、最新の共有変更と統合・検証された。
- [ ] `main` への merge と push が完了し、共有 `origin/main` に含まれることを確認した。
- [ ] 利用者が続けて見るサーバーは動作を保ち、状態と実際の URL を伝えた。停止は利用者が試し終えた時、停止を依頼した時、または引き渡しに使わない検証専用プロセスに限った。

変更なしのテストでは commit / push は不要です。中断や同期失敗の場合は、変更の保存場所と残作業を報告します。

## 日本語での報告テンプレート

起動だけなら、対象名・実際の URL・動作中であること・停止方法・未確認範囲を短く伝えます。以下は変更を共有する場合のテンプレートです。

```text
対象: プロトタイプ名
変更: 利用者から見て何が変わったか
確認済み: 実行したテスト・ビルド・実画面の結果
未確認 / 問題: 実機確認が必要な点、残る問題
保存・共有: ブランチ、commit ID、GitHub main への反映結果
更新ノート: share/ 内の今回の記録へのリンク
次回: 開く場所・URL、再開する場合の残作業
```

確認した環境が結果に影響する場合は OS、ブラウザー、Node.js、対象の seed / 設定も記録します。GitHub へ反映できていない場合は、その状態を省略しません。
