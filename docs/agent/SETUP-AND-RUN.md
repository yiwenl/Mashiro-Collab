# 環境を準備してプロトタイプを実行する

## まず確認すること

この手順は agent が実行します。利用者にコマンド一覧を渡すだけで終わらず、最後に動作中の画面または URL を渡してください。入口は [ルート README](../../README.md) です。

まず利用者の PC で実行できることを確認し、OS、CPU、使用中の shell、作業フォルダーを調べます。クラウドのコンテナーだけで起動した localhost は、利用者の PC から開ける URL ではありません。利用者の PC を操作する手段がない場合は必要な接続・実行環境を具体的に伝えます。

macOS / Linux の shell 手順を Windows PowerShell にそのまま貼り付けないでください。既存環境を使える場合は再インストールしません。

```sh
git --version
node --version
npm --version
```

- Git: 共同作業の履歴・同期に使用します。
- Node.js: 開発サーバーやビルドを動かします。
- npm: Node.js のパッケージをインストールします。通常は Node.js と一緒に導入します。

対象プロトタイプの `.nvmrc`、`package.json`、README を確認し、指定されたバージョンを使います。**circles08 は Node.js 22** です。別の案に無条件で同じバージョンを適用しません。

## Git / Node.js がない場合

agent が既存の管理方法を確認して不足分を導入します。Git は [公式配布ページ](https://git-scm.com/downloads)、Node.js は [公式配布ページ](https://nodejs.org/en/download) の、OS・CPU に合う方法を使います。circles08 用には Node.js 22 を選びます。「最新」の表示だけで別の major バージョンを選びません。

- **macOS:** 既存のバージョン管理ツールを優先します。ない場合は適切な公式 installer で導入を進めます。Git の実行で開発ツールの導入画面が出たら、本人の許可が必要な操作を案内します。
- **Windows:** 既存の Node.js 管理方法か、対応する公式 installer を使います。インストール後は新しい terminal / agent session で PATH を再確認します。PowerShell が `npm.ps1` を拒否する場合は同じ Node.js に含まれる `npm.cmd` を使えます。PC 全体の実行ポリシーを変更する必要はありません。
- **Linux:** 既存のバージョン管理ツールか公式案内の対応方法を使います。配布パッケージの Node.js が対象バージョンに合うか確認します。

`nvm` がすでに利用できる macOS / Linux 環境では、対象プロトタイプに移動して `nvm install`、`nvm use` を実行できます。Windows で同じ `nvm` の挙動を仮定しません。

GUI installer の権限許可やログインなど本人の操作が必要な時だけ、短い日本語で案内し、完了後は agent が続けます。導入後に PATH を読み直すか新しい terminal を使い、上の三つのバージョン確認を再実行します。

`node` はあるのに `npm` がない場合は、PATH と選択中の Node.js を確認し、npm を含む指定バージョンの導入を修復します。別の major の Node.js や最新 npm を無条件に上書きしません。

## ソースと依存関係

未取得なら [Git ガイド](GIT-WORKFLOW.md) に従って clone します。取得済みなら、**テストを始める前にそのガイドの開始前手順を完了**してください。

以降はリポジトリのルートから、対象プロトタイプへ移動します。circles08 の例:

```sh
cd prototypes/circles08
npm ci
```

ここに `package.json` と `package-lock.json` があることを確認してから実行します。ルート、`config/`、`vendor/` ではインストールしません。

`npm ci` は lockfile に固定された依存関係を入れ直します。通常の準備では `npm install` で lockfile を更新しません。初回・lockfile の変更時・Node.js の変更時に再実行し、同じセッションで画面を確認するたびに再インストールする必要はありません。[npm の仕様](https://docs.npmjs.com/cli/v11/commands/npm-ci/)

依存追加・更新そのものが依頼の対象なら、その変更理由を明確にし、manifest と lockfile を一緒に更新・検証します。起動のためだけに `npm audit fix --force` や一括アップグレードを行いません。

circles08 は npm の公開パッケージと同梱の `vendor/` を使用します。別リポジトリの checkout、npm ログイン、API key、`.env` の作成は通常不要です。GitHub の読み取り認証は取得時に必要な場合だけ行い、作者情報と書き込み権限の準備は変更を共有する時に行います。

## 起動と成功の確認

circles08 のフォルダーで:

```sh
npm start
```

開発サーバーは動き続けるプロセスです。agent は**返信後も継続する terminal / 実行セッション**を使い、作業ディレクトリ・プロセスまたはセッション ID・URL・停止方法を把握します。短い時間制限で自動終了する実行方法を使ったまま、完了としません。

1. 起動ログでコンパイルの成功を確認します。circles08 の既定 URL は [http://127.0.0.1:8083/](http://127.0.0.1:8083/) です。設定やログから実際のポートを確認します。
2. 利用者の PC からその URL に HTTP 接続し、成功応答と circles08 の HTML を確認します。現在の HTML の title は `Circles 08 — 3D Difference` です。`curl`、PowerShell の `Invoke-WebRequest`、agent のブラウザーツールなど、利用できる方法で確認します。別プロジェクトのページを成功扱いにしません。
3. 操作可能なら**利用者に見えるブラウザー**で URL を開き、図形、右上の操作パネル、左上の FPS、console のエラーを確認します。検証用の非表示ブラウザーだけで済ませず、利用者が開ける URL も伝えます。
4. ブラウザー操作ができない場合は、HTTP 応答を確認した URL をクリックできるリンクで渡し、「画面表示は直接確認できていません」と添えます。URL の引き渡しを本人の画面確認待ちで止めません。HTTP 接続もできていなければ、その URL を確認済みとは呼ばず、問題を解決します。
5. サーバーがまだ動作していることを確認し、対象名・実際の URL・サーバーを動かしたままであることを日本語で短く伝えます。停止したい時は agent に依頼できることも添えます。利用者が後で自分で停止できるよう、terminal を使った場合はその場所も示します。

これで初回起動の引き渡しは完了です。ファイルに変更がなければ commit / push は不要です。全テスト・ビルド・カメラ確認は初回起動の必須条件ではありません。表示に問題がある場合や利用者が調整を依頼した場合は、関係するガイドに従って続けます。

8083 が使用中なら、使用者不明のプロセスを終了せず、既存サーバーの対象を確認するか空いているポートを選びます。

```sh
npm start -- --port 8084
```

8084 も空いているか確認し、使用した場合の URL は `http://127.0.0.1:8084/` です。案内するリンクも実際のポートに合わせます。別プロトタイプはその README のポートと起動方法を使います。

## カメラを使用する circles08 の条件

カメラは画面を開いた後、利用者が試す時に案内します。起動だけの依頼で自動的に追跡を開始したり、カメラの許可待ちにしたりしません。

- WebGL 2 に対応するブラウザーが必要です。Color モードには追加の GPU 機能が必要で、非対応時は Difference に切り替わります。
- **Start tracking** 後のカメラ許可は本人に依頼します。OS とブラウザーの両方の設定が関係する場合があります。
- カメラは localhost / `127.0.0.1` または HTTPS で使用します。HTML の直接オープンや通常の HTTP LAN アドレスで代用しません。
- 追跡開始時に外部 CDN の WASM / モデルが必要です。依存関係のインストール完了だけではオフライン利用可能とは判断しません。
- Digit は手、Kinetic は上半身と両手を映して確認します。詳細は [対象の README](../../prototypes/circles08/README.md) を読みます。

## 停止・再開

**初回起動の返信時には停止しません。** 利用者が試し終えた、または停止を依頼した時に、カメラ使用中なら先に画面の **Stop camera** を押します。その後、起動した terminal で Ctrl+C、または agent が管理するそのプロセスを停止します。他の Node.js プロセスをまとめて終了しません。

後日再開する時は Git 更新から始めます。同じセッションの再起動なら対象フォルダーで `npm start` を実行します。
